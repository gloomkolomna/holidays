# 🎉 Улица праздников — AGENTS.md

## Проект

VK Mini App «Улица праздников» — приложение тематических ивентов-коллекций
в той же экосистеме, что «Ферма» (реальная вышивка → «крестики»).

Игровая идея (первая часть — `docs/idea.txt`), уточнённая интервью
2026-10-20 (решения пользователя — источник истины вместе с `docs/PLAN.md`):

- **Праздники создаёт admin в админке**: даты **С и ПО** (автоматически;
  время фиксировано: начало `00:00:00`, окончание `23:59:59` МСК,
  админ выбирает только даты, однодневный праздник валиден),
  категории (**название + норма в крестиках**) и **сетка карточек по
  дням** — в каждой категории по одному слоту на каждый день праздника
  (генерируется автоматически, админ заполняет: название, задание,
  изображение).
  **Терминология: в UI и API ивент называется «праздник»** (модель
  `Holiday`, таблицы `holidays`/`holiday_categories`/`holiday_cards`,
  пути `/api/holidays`); в `docs/idea.txt` используется слово «ивент» —
  это одно и то же.
- Игра **бесплатная**, доступ — **всем подписчикам группы** ВК.
  Гейт на входе: проверка подписки через VK API `groups.isMember`
  при логине; неподписчику — экран
  «подпишитесь на группу» с перепроверкой. Подписок, платежей и
  дон-гейта как в «Ферме» здесь **нет**.
- **Слайдер дня**: игроку в конкретный день показываются карточки этого
  дня (по одной из каждой категории) в слайдере: название, изображение
  (зум в модальном окне), норма, задание и кнопка **«Принять»**.
  **Активное задание строго одно**, но от него можно **отказаться**
  (кнопка «Отказаться от задания») и выбрать другое; после сдачи в тот
  же день можно принять следующую карточку дня. Карточки прошедших дней
  **нигде не удаляются** (остаются в БД и коллекции); догон несобранных
  карточек — через «Магазин» по выходным (см. ниже). Взятая
  карточка сдаётся и после закрытия праздника.
- **Баланса крестиков НЕТ.** «Крестики» — число, которое игрок вписывает
  в отчёт (с фото); система проверяет его против **нормы категории
  карточки** — у каждой категории карточек праздника своя норма в
  крестиках (название + норма задаёт админ; карточки создаются внутри
  категории с заданием и изображением).
- Отчёт: **фото до/после + число крестиков, авто-зачёт** (без
  модерации). Один отчёт закрывает ровно одну карточку, излишек
  сверх нормы сгорает. Число >= нормы → карточка в **коллекцию**.
- **Штраф — фиксированные 1000 крестиков** (не ×2). Применяется к
  выкупленным карточкам: после закрытия праздника несобранные карточки
  можно взять в разделе **«Магазин»** — карточка становится штрафным
  заданием (отчёт >= 1000). Штрафное занимает тот же единый слот
  активного задания, отказаться/заменить нельзя. **Магазин открыт
  только по субботам и воскресеньям** (время московское); в будни —
  экран «откроется в субботу», выкуп через API запрещён (400).
- **Кристаллы + кубок — за каждый полностью собранный раздел
  (категорию)**: раздел полон, когда собраны все его заполненные
  карточки (пустые админские черновики не считаются; concept
  «кубковой карточки» удалён — is_trophy больше нет). За каждый
  полный раздел — +1 кристалл и **«кубок категории»** — свой PNG
  у каждой категории (максимум = число разделов), однократно,
  в любой момент полноты (успел в ивент или добрал через магазин —
  не важно). Общего кубка праздника нет. Кристаллы тратятся в
  **«лавке наград»** на товары внешних приложений (промокоды для
  «Фермы»/«Драконов» и т.п.).
- Во время ивента **фоновый поток API** постит в группу ВК итоги
  предыдущего дня (что добавилось в коллекции всех игроков).
- Дизайн главной страницы меняется под тематику каждого ивента:
  палитра + фоновая картинка от админа + пресет анимации (2–3 готовых).
- **Запуск: первый ивент — Хеллоуин 31.10** — MVP (каркас, ивенты,
  тройка/отчёты/коллекция, простое оформление, деплой); магазин,
  лавка наград и бот — сразу после запуска. v1 — соло, без соц. блока
  (чужие коллекции/рейтинги — позже). Одновременно активен **один**
  ивент.

С «Фермой» общее — только конвенции разработки (стек/миграции/деплой),
игровых пересечений в v1 нет. Не додумывать механику сверх

## База данных — ключевые таблицы (планируемые)

Финальная схема фиксируется при планировании (`docs/PLAN.md`).
Ориентир по сущностям из идеи и решений интервью:

- **users** — `vk_id` PK, `role` (admin/player), `crystals`, `display_name`
- **settings** — key-value настройки (норма ивента по умолчанию, бот, ...)
- **holidays** — праздники/ивенты (название, сроки, тема)
- **holiday_categories** — категории карточек праздника (название,
  норма крестиков)
- **holiday_cards** — сетка карточек: категория × **день показа**,
  название, задание (`task_text`), изображение (пустой слот = черновик)
- **daily_offers** — тройка карточек дня игрока (24 часа, факт взятия)
- **user_cards** — коллекция игрока (собранные карточки, UNIQUE user+card)
- **penalty_tasks** — выкупленные задания со штрафом ×2 (одно активное)
- **stitch_reports** — отчёты (фото + число крестиков, авто-зачёт)
- **collection_rewards** — начисленные кристаллы за полные коллекции
- **reward_items / reward_codes / reward_purchases** — лавка наград
  (товары с ценой в кристаллах, пул промокодов, покупки)
- **group_posts** — история постов бота в группу ВК
- **logs** — для middleware

## Роли и права

- **admin** — управление настройками, управление ивентами (создание/каталог
  карточек/сроки), модерация (если включена).
- **player** — всё геймплейное.

Роль `admin` назначается по `ADMIN_VK_IDS` при логине (см. `routes/auth.py`).

## Ключевая механика — крестики

- **Баланса нет.** Игрок в отчёте (фото + `amount` крестиков) заявляет,
  сколько вышил. Проверка: `amount >= norm_crosses` категории карточки.
- **Слайдер дня:** карточки показываются строго в свой день (по одной из
  каждой категории); кнопка «Принять» создаёт задание с зафиксированной
  нормой категории. Одно активное задание; после сдачи можно принять
  другую карточку этого же дня.
- **Сдача задания**: две кнопки — **«Норма»** (amount >= нормы
  категории) и **«Штраф»** (amount >= нормы × 2), обе требуют фото
  «до/после». Фото отчётов при `S3_ENABLED` уходят в Яндекс.Облако
  (bucket `korgiholidays`, ключ `{vk_id}/...`), иначе — локально;
  HEIC с iPhone поддержан (pillow-heif + сжатие на клиенте).
- **Штраф**: ровно **1000 крестиков** — для выкупленных в «Магазине»
  карточек завершённых праздников (магазин открыт **сб+вс** по МСК);
  одно активное штрафное задание, отказаться нельзя.
- **Кристаллы:** +1 за каждый полностью собранный раздел праздника
  (однократно; кубок — свой PNG каждой категории), тратятся в лавке
  наград на промокоды внешних приложений.

Открытые детали (генерация тройки, таймзона суток, посты бота,
темы оформления) — только через `docs/PLAN.md` и утверждение
пользователем, не додумывать.

## Миграции

```powershell
cd api
.\venv\Scripts\python.exe -m alembic upgrade head
```

`alembic.ini` в `api/`, `env.py` переопределяет URL из `config.DATABASE_URL`.
Миграции **НЕ применяются при runtime** — `init_db()` делает `create_all`
для безопасности, реальные изменения схемы через `alembic upgrade head`.

### ⛔ Обязательно: миграция после ЛЮБОГО изменения models.py

**Правило:** если ты изменил(а) `api/models.py` (добавил/удалил колонку,
новую таблицу, изменил тип колонки, переименовал) — ОБЯЗАТЕЛЬНО:

1. **Создать миграцию:**
   ```powershell
   cd api
   .\venv\Scripts\python.exe -m alembic revision --autogenerate -m "краткое_описание"
   ```
2. **Проверить** содержимое сгенерированного файла в `api/alembic/versions/` — autogenerate иногда добавляет лишние изменения (NOT NULL, type changes), их можно оставить, если они корректны.
3. **Применить миграцию:**
   ```powershell
   cd api
   .\venv\Scripts\python.exe -m alembic upgrade head
   ```
4. **Убедиться, что dev.ps1 тоже применит миграцию** (на старте dev.ps1 делает `alembic upgrade head` автоматически — нужно просто перезапустить сервер).

**⛔ С 2026-10-20 базу НЕ пересоздавать** (раньше при структурных
изменениях dev-БД пересоздавалась целиком с единой миграцией 0001) —
теперь любые изменения схемы ТОЛЬКО через новые миграции
`alembic revision --autogenerate` + `upgrade head`.

Без миграции прод-БД и dev-БД не будут соответствовать моделям → 500 ошибки «no such column» или «no such table».

## ⛔ Обязательно: тесты на каждое изменение (НЕПРЕЛОЖНОЕ ПРАВИЛО)

Это правило нарушать нельзя — ни в одной задаче. Тесты — это часть определения
сделанного, а не отдельный шаг «на потом».

**Правило:** после ЛЮБОГО изменения Python-кода — ОБЯЗАТЕЛЬНО:

1. **Написать тесты** на новое поведение: happy path, ошибки (4xx), права.
2. **Запустить полный набор:**
   ```powershell
   cd api
   .\venv\Scripts\python.exe -m pytest tests/ -v --tb=short
   ```
3. **Добиться зелёного.**
4. **Не удалять старые тесты** ради прохождения новых — признак регрессии.

**Паттерны тестов** (см. `api/tests/conftest.py`):
- In-memory SQLite + `StaticPool`, env до импорта config/db.
- Авторизация через фикстуры-клиенты, НЕ через ручную подстановку токенов.
- Сиды ивентов/карточек/настроек — в `conftest.py` (аналог `seed_farm` из «Фермы»).

## Деплой

Полнооткатный скрипт `deploy/deploy.sh` (структурно идентичен Ферме/lostworld/dragons):

1. Фиксация `PREV_REV` (Alembic) + `PREV_GIT`.
2. tar-бэкап + бэкап БД + бэкап dist.
3. `git fetch` + `reset --hard`.
4. `pip install` + `alembic upgrade head`.
5. `npm install` + `npm run build`.
6. `systemctl restart <service>`.
7. Health-check (5 попыток).

При ошибке — `trap on_error` → `rollback_all`. Режим `-recovery` —
интерактивное восстановление из tar-архива.

Константы (`APP_DIR`, имя systemd-сервиса, порт, location nginx, имя БД)
фиксируются при настройке деплоя — НЕ копировать фермерские
(`magicfarm`/`farm.db`/8003) без утверждения пользователем.

## ⚠️ Кодировки файлов (НЕПРЕЛОЖНОЕ ПРАВИЛО)

**Все исходники проекта — UTF-8 без BOM, переводы строк LF.** Кириллица в
`frontend/src/*.tsx`, `api/*.py`, `docs/*.md` и т.д. обязана оставаться UTF-8.

**ЗАПРЕЩЕНО использовать PowerShell-командлеты для чтения/записи файлов проекта:**
`Get-Content`, `Set-Content`, `Out-File`, `Add-Content`, `>` и т.п.
PowerShell 5.1 без явного `-Encoding` читает файл без BOM как Windows-1251
(системная локаль) и пишет обратно в другой кодировке → **вся кириллица в файле
превращается в «кракозябры»** (`в”Ђ` / `Р РµС†` и т.п.), а LF → CRLF.
Именно так однажды была сломана кодировка `frontend/src/pages/Admin.tsx`.

**Можно и нужно:**
- Читать/редактировать файлы только штатными инструментами (Read/Write/Edit) —
  они сохраняют UTF-8.
- Если обойтись без шелла нельзя — использовать Python с явной кодировкой:
  ```powershell
  api\venv\Scripts\python.exe -c "data=open('frontend/src/pages/Admin.tsx',encoding='utf-8').read(); ..."
  ```
  (запись всегда `open(path, 'w', encoding='utf-8', newline='\n')`).
- Обрезка/удаление хвоста файла через `Get-Content | Set-Content` — **запрещено**.

## 🔍 Graphify — граф знаний проекта

This project has a graphify knowledge graph at graphify-out/.

### Rules:

- Before answering architecture or codebase questions, read graphify-out/GRAPH_REPORT.md for god nodes and community structure
- If graphify-out/wiki/index.md exists, navigate it instead of reading raw files
- After modifying code files in this session, run graphify update . to keep the graph current (AST-only, no API cost)

При **любом поиске по коду** — сначала использовать graphify, а не grep/glob:

```powershell
cd api
.\venv\Scripts\python.exe -m graphify query "<вопрос>"
```

Граф построен для всего проекта (`graphify-out/graph.json`) и покрывает:
- API-роуты, модели, сервисы, тесты
- Фронтенд: страницы, компоненты, контексты, API-клиент

**После создания/удаления файлов** — обновить граф:

```powershell
cd api
.\venv\Scripts\python.exe -m graphify update "D:/Боты/Улица праздников"
```

(Пока в проекте нет своего venv — граф можно обновлять питоном из venv
«Фермы»: `D:/Боты/Ферма/api/venv/Scripts/python.exe -m graphify update <путь>`.)
