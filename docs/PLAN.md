# PLAN — Улица праздников (VK Mini App)

План реализации по конвенциям «Фермы» (`D:\Боты\Ферма`), перенос 1:1:
стек, структура api/frontend, auth (VK sign + JWT), Alembic, тесты
(in-memory SQLite + фикстуры-клиенты), middleware логов, деплой
с полным откатом.

Источник идем: `docs/idea.txt` (часть 1) + интервью 2026-10-20
(два раунда: базовый + глубокий).

**Запуск: первый ивент — Хеллоуин 31.10.2026** (MVP-срез ниже).

## Решено (интервью 2026-10-20)

| Вопрос | Решение |
|---|---|
| Ивенты | Создаёт **admin в админке**: название, **сроки С и ПО** (открытие/закрытие автоматически по датам), норма, тема, **загрузка карточек**. Ивентов много — по одному на каждый праздник (Хеллоуин, Рождество и т.д.) |
| Доступ | Игра **бесплатная**, вход — **только подписчикам группы** ВК. Гейт при логине: VK API `groups.isMember` (сервисный токен). Подписок/платежей/дон-гейта «Фермы» нет |
| Баланс крестиков | **НЕТ баланса.** Крестики — число в отчёте, сверяется с нормой ивента (настройка админа, по умолчанию 1000) |
| Связь с «Фермой» | Только конвенции разработки. Игровых пересечений в v1 нет |
| Формат отчёта | **Фото до/после + число крестиков, авто-зачёт** (без модерации). **1 отчёт = 1 карточка**, излишек сверх нормы сгорает |
| Норма | **У каждой категории карточек своя норма** в крестиках (админ задаёт название + норму при создании категории праздника); карточка наследует норму категории (обновлено 2026-10-20, было: единая на ивент) |
| Тройка дня → Сетка дней | **Замена 2026-10-20:** случайной тройки больше нет. Админ задаёт карточки **по дням**: в каждой категории автоматически генерируется по одному слоту на каждый день праздника (заполняются название/задание/изображение). Игроку в день показываются карточки этого дня (по одной из каждой категории) в **слайдере** с кнопкой «Принять». После сдачи можно принять другую карточку этого же дня. Карточки прошедших дней **не удаляются нигде** (остаются в БД и коллекции); в дальнейшем игрок сможет **по воскресеньям выбирать** карточки прошедших дней (см. блок «Воскресный догон») |
| Активное задание | **Строго одно (единый слот)**, но можно **отказаться** от активного задания и взять/выбрать другое (обновлено 2026-10-20 — раньше «отказаться нельзя»). Взятая карточка сдаётся по норме даже после закрытия праздника |
| Штраф | **Фиксированные 1000 крестиков** — задание при выкупе карточки после завершения праздника («Магазин», этап 3). Обновлено 2026-10-20 (было: ×2 от нормы) |
| Магазин выкупа | После завершения ивента; несобранная карточка → штрафное задание ×2; занимает единый слот; отказаться/заменить нельзя |
| Кристаллы и кубок | За каждую **полностью собранную коллекцию** — **+1 кристалл + кубок**, в **любой момент** полноты (успел в ивент или добрал через магазин — не важно). Кристаллы — валюта **лавки наград** (промокоды для «Фермы»/«Драконов» и т.п.) |
| Посты в группу | **Фоновый поток в API** (как подписочные задачи «Фермы»), VK API `wall.post` |
| Запуск | **Первый ивент — Хеллоуин 31.10.2026** (MVP ниже), дальше — по календарю праздников |
| Соц-блок | **Нет в v1** (соло: свой профиль, свои коллекции/кубки; чужие/рейтинги — позже) |
| Темы оформления | **Пресеты анимации (2–3 готовых) + фон/палитра на ивенте, грузит админ** — новый ивент без релиза кода |
| Параллельные ивенты | **Один активный** в v1; админ планирует непересекающиеся сроки |

## Допущения (прямые следствия решений — возразите, поменяем)

1. Карточка доступна **только в свой день** (МСК); при смене дат
   праздника пустые слоты исчезнувших дней удаляются, заполненные и
   собранные карточки остаются.
2. Штрафное задание из магазина занимает **тот же единый слот**:
   пока оно не сдано, дневные карточки не принимаются (магазин
   доступен только для завершённых праздников — пересечение возможно,
   когда уже есть завершённый праздник и идёт новый).
3. Излишек крестиков сверх нормы в отчёте просто сгорает (баланса нет).
4. Если дата «ПО» — 00:00, последний день сетки — накануне
   (`holiday_days` в `services/cards_grid.py`).

## Открытые вопросы (принять перед/в ходе соответствующего этапа)

1. **Сутки и таймзона.** Рекомендация (принять по умолчанию): смена дня
   в 00:00 МСК (`services/msk_time.py` по конвенции «Фермы»); время
   поста бота — настройка (по умолчанию 09:00 МСК).
2. **Магазин: «иногда выкупать».** Рекомендация v1: без лимитов, пока
   у ивента стоит флаг `shop_enabled`.
3. **Промокоды: механика выдачи.** Рекомендация v1: у товара пул кодов,
   покупка снимает один (закончились — «нет в наличии»); redemption
   кодов в «Ферме»/«Драконах» — вне скоупа этого приложения.
4. **Контент Хеллоуина:** число карточек, норма, длительность (С и ПО) —
   задаёт админ; для dev/тестов — сид в `conftest.py`.
5. **Деплой-константы:** порт API (Ферма заняла 8003 — предложить 8004),
   имя systemd-сервиса, `APP_DIR`, nginx location, git-репозиторий,
   `VK_APP_ID/SECRET` нового мини-приложения (создать в ВК).
6. **Статистика профиля** (суммарно вышито крестиков, история отчётов) —
   рекомендуем минимальный профиль; решить на этапе 2.
7. **Перепроверка подписки на группу.** Рекомендация: кэш членства в БД
   (`users.member_cached_at`), ленивая перепроверка не чаще раза в
   сутки; отписавшийся теряет доступ при следующей проверке.

## Схема БД (ориентир, детали — в момент реализации)

- `users` — vk_id PK, role, display_name, **crystals**, member_cached_at,
  created_at
- `settings` — key-value
- `holidays` — title, starts_at, ends_at, тема
  (bg_image_url, palette, animation_preset), shop_enabled
- `holiday_categories` — holiday_id FK, title, `norm_crosses`
  (норма категории)
- `holiday_cards` — holiday_id FK, category_id FK, title,
  `task_text` (задание), image_url, sort_order
- `daily_offers` — user_id, event_id, day (МСК), card_id, offered_at,
  task_id NULL — UNIQUE(user, event, day, card)
- `tasks` — **единая таблица заданий**: user_id, event_id, card_id,
  kind (daily/penalty), required_crosses, status (active/done),
  taken_at, done_at — частичный UNIQUE(user_id) WHERE status='active'
  (гарантирует единый слот)
- `user_cards` — user_id, card_id, source (daily/penalty), earned_at —
  UNIQUE(user_id, card_id)
- `stitch_reports` — user_id, task_id, amount, photo_before/after +
  превью, created_at (+анти-дубль 10 сек по конвенции «Фермы»)
- `collection_rewards` — user_id, event_id, crystals=1, **кубок**
  (= сам факт записи), awarded_at — UNIQUE(user_id, event_id)
- `reward_items` — title, description, image_url, price_crystals,
  is_active
- `reward_codes` — item_id, code, taken_by NULL, taken_at NULL
- `reward_purchases` — user_id, item_id, code_id, created_at
- `group_posts` — event_id, day, text, posted_at — UNIQUE(event, day)
- `logs` — middleware
